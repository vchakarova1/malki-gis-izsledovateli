# Малки ГИС изследователи

„Малки ГИС изследователи“ е образователен уеб проект за ученици от 1. до 4. клас.

Проектът насърчава децата да изследват България, да откриват географски и литературни връзки, да задават въпроси и да развиват дигитално и пространствено мислене.

## Реализирано до момента

- Адаптивна начална страница.
- Hero секция с илюстрирана карта на България.
- Образователен карусел с четири направления.
- Интерактивен свитък „Учим заедно“.
- Отделна страница с интерактивна ArcGIS карта.
- Отделна страница „Лаборатория на откритията“.
- Адаптивно оформление за desktop, tablet и mobile.
- Основни достъпни HTML елементи и клавиатурна навигация.
- Fallback поведение при проблем със зареждането на ArcGIS картата.

## Публични страници

- `index.html` — начална страница.
- `map.html` — интерактивна карта на България.
- `missions.html` — визуална основа за бъдещи мисии и ученически проекти.

Публичното съдържание е достъпно без вход.

## Технологичен стек

- HTML
- CSS
- JavaScript
- Bootstrap
- Vite
- Node.js и npm
- ArcGIS Instant App чрез външен iframe

Проектът не използва React или TypeScript.

## Стартиране локално

Инсталиране на зависимостите:

```bash
npm install
```

Стартиране на development сървъра:

```bash
npm run dev
```

След стартиране основните страници са:

- `/`
- `/map.html`
- `/missions.html`

## Production build

```bash
npm run build
```

За локален преглед на production build:

```bash
npm run preview
```

## Тестове и проверки

Към момента проектът има build проверка чрез:

```bash
npm run build
```

Автоматизирана тестова команда не е конфигурирана.

При добавяне на нови функционалности трябва да се проверяват:

- коректното зареждане на страниците;
- desktop, tablet и mobile изгледът;
- липсата на хоризонтално препълване;
- навигационните връзки;
- достъпността;
- запазването на съществуващите функционалности.

## Текущ статус

Публичната визуална основа на проекта е реализирана.

Все още предстои разработването на:

- удостоверяване на потребители;
- роли за ученик, учител и администратор;
- защитени пространства;
- база данни;
- мисии и управление на учебно съдържание;
- ученически проекти и споделяне;
- Supabase таблици и политики;
- deployment и крайна проверка на публикуваната версия.

## Supabase и сигурност

Supabase ще бъде добавен на следващ етап.

Предстоящата реализация трябва да включва:

- конфигурация чрез environment variables;
- удостоверяване;
- роли и права за достъп;
- защитени таблици;
- Row Level Security (RLS);
- политики за публично и защитено съдържание;
- проверка на достъпа от страна на сървъра и базата данни.

Секретни ключове, пароли и service-role ключове не трябва да се записват в Git или в README.

SQL миграциите трябва да се съхраняват в:

```text
supabase/migrations/
```

Преди прилагане на промени в базата данни трябва да се създаде локален SQL migration файл и да се провери съответствието му със Supabase схемата.

## Планирани роли

### Гост

- Достъп до публичната начална страница.
- Достъп до публичната карта.
- Достъп до публичното съдържание на лабораторията.

### Ученик

Предстои да получи защитено пространство за:

- преглед на мисии;
- работа по учебни предизвикателства;
- създаване или записване на ученически проекти;
- преглед и споделяне на разрешено съдържание.

### Учител

Предстои да получи защитено пространство за:

- управление на учебно съдържание;
- преглед на ученически работи;
- организиране на образователни дейности.

### Администратор

Предстои да получи защитено пространство за:

- управление на потребители;
- управление на роли;
- контрол на съдържанието и системните настройки.

Тези роли и пространства все още не са реализирани.

## Git workflow

Всеки самостоятелен етап от разработката трябва да се изпълнява в отделен Git branch.

Branch-овете трябва да имат ясни имена, например:

```text
feature/supabase-auth
feature/student-space
feature/teacher-space
feature/admin-space
```

Commit съобщенията трябва да описват конкретната промяна.

Преди сливане трябва да се проверят:

- build-ът;
- засегнатите функционалности;
- достъпността;
- responsive поведението;
- липсата на чувствителни данни.
