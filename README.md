# Малки ГИС изследователи

„Малки ГИС изследователи“ е образователно уеб приложение за ученици от 1. до 4. клас. То насърчава децата да изследват България, да откриват географски и литературни връзки и да развиват дигитално и пространствено мислене.

## Технологии

- HTML, CSS и JavaScript;
- Bootstrap;
- Vite като multi-page приложение;
- Supabase JS;
- Supabase Auth;
- PostgreSQL и Row Level Security (RLS);
- ArcGIS Instant App чрез външен responsive iframe;
- Git и GitHub.

Проектът не използва React или TypeScript. Клиентът използва publishable/anon конфигурация чрез environment variables. Service-role ключове и други тайни не се записват в Git, README или browser кода.

## Страници

- `index.html` — публична начална страница;
- `map.html` — интерактивна ArcGIS карта на България;
- `missions.html` — публична „Лаборатория на откритията“;
- `auth.html` — регистрация и вход;
- `profile.html` — защитен профил и изход;
- `student.html` — защитено ученическо работно пространство.

Публичните страници са достъпни без вход. Защитените страници проверяват текущата Supabase сесия.

## Основни JavaScript модули

- `src/main.js` — начална страница и основната публична навигация;
- `src/map-page.js` — ArcGIS iframe, responsive карта, fallback и retry;
- `src/missions-page.js` — „Лаборатория на откритията“ и ролите;
- `src/auth-page.js` — регистрация и вход чрез Supabase Auth;
- `src/profile-page.js` — session guard, профил, роля и изход;
- `src/student-page.js` — ученически работен лист и маршрути;
- `src/supabase-client.js` — единственият browser Supabase клиент.

## Реализирано към 03.11.2026 г.

### Frontend

- адаптивна начална страница с образователни секции;
- публична ArcGIS Instant App карта с fallback при проблем със зареждането;
- публична „Лаборатория на откритията“;
- регистрация и вход чрез Supabase Auth;
- автоматичен redirect към профила след вход;
- защитена профилна страница с показване на ролята и изход;
- ученически работен лист с динамични точки;
- добавяне на име, населено място, координати и бележка към точка;
- създаване и записване на маршрут като `draft`;
- изпращане на маршрут като `submitted`;
- редактиране само на собствени чернови.

### База данни и сигурност

- при регистрация се създава профил с начална роля `student` чрез Auth trigger;
- налични са ролите `student`, `teacher` и `admin`;
- RLS защитава собствените ученически маршрути;
- ученик може да бъде свързан с учител чрез teacher join код чрез database RPC;
- администраторски RPC функции генерират/ротират и отменят teacher join кодове;
- кодовете се генерират с криптографски случайни байтове и се показват на администратора при генериране или ротация; в базата се съхранява само hash, а кодът се показва във формат `XXXXX-XXXXX`.

### Какво е работещо и какво е само в базата

Работят frontend функциите за Auth, профил, ученическо пространство и маршрути.

В Supabase, но все още без съответен потребителски интерфейс, съществуват:

- `join_teacher(p_join_code text)` — защитена функция за присъединяване на ученик към учител;
- `admin_rotate_teacher_join_code(p_teacher_id uuid)` — генериране/ротация на teacher код;
- `admin_revoke_teacher_join_code(p_teacher_id uuid)` — отнемане на teacher код.

Все още няма frontend форма за въвеждане на join код и няма teacher или admin панел.

## Supabase структура

### `public.profiles`

Профилите са свързани с Auth потребителите и съдържат основно:

- `id` — UUID на Auth потребителя;
- `created_at`;
- `role` — `student`, `teacher` или `admin`;
- `teacher_id` — връзка от ученически профил към учителски профил;
- `teacher_join_code_hash` — hash на активния teacher join код.

`teacher_id` има foreign key към `public.profiles(id)` и се валидира така, че да сочи към teacher профил. Join кодът не се съхранява в оригинален вид.

### `public.routes`

Маршрутите съдържат основно:

- `id`;
- `student_id`;
- `title`;
- `selected_stops`;
- `annotation`;
- `status` — текущите статуси са `draft` и `submitted`; `accepted` е бъдещ статус след учителска проверка;
- `created_at` и `updated_at`.

`routes.student_id` е foreign key към `auth.users(id)`, а не директен foreign key към `profiles(id)`. Той идентифицира ученика чрез същия Auth UUID, използван от неговия профил.

Таблиците `profiles` и `routes` се запазват. Те не трябва да се променят без предварителен анализ и изрично одобрение.

## Учителска и административна функционалност

Следните функции са предстоящи и не трябва да се представят като вече реализирани:

- teacher dashboard;
- присъединяване към учител чрез код от потребителския интерфейс;
- read-only достъп на учителя до маршрутите на свързаните ученици;
- проверка на ученически работи;
- формативна обратна връзка;
- admin интерфейс;
- управление и одобрение на публикации.

## Бъдеща архитектура

Съществуващите `profiles` и `routes` се запазват. Предвиждат се следните нови таблици:

- `assignments` — работни задачи и общ шаблон на работния лист;
- `assignment_recipients` — получатели на задача;
- `teacher_reviews` — окончателна формативна обратна връзка;
- `publications` — предложения и одобрени публични представяния.

Задачите могат да се изпращат към цял клас, група или индивидуален ученик. Приетото решение за групите е групата да използва обикновен student акаунт с един `student_id`, една задача, един работен лист и една окончателна обратна връзка; няма да се създават специална групова таблица или групова роля.

За всеки работен лист се предвижда една окончателна формативна обратна връзка с ниво и коментар. Това не е цифрова училищна оценка.

Планираният поток за публикации е:

1. учителят предлага цялата работа за публично представяне;
2. администраторът преглежда и одобрява;
3. администраторът може да редактира публичното представяне;
4. администраторът публикува материала.

## ArcGIS Instant App, StoryMap и „Лаборатория“

ArcGIS Instant App е интегриран чрез външен iframe в картовите страници и ученическото работно пространство.

Отделният образователен StoryMap все още не е интегриран в приложението и не е свързан като карта в „Лабораторията“. Интеграцията е бъдеща задача. Конкурсното съдържание не трябва да се променя, копира или публикува прибързано.

## Стартиране локално

Инсталиране на зависимостите:

```bash
npm install
```

Стартиране на development сървъра:

```bash
npm run dev
```

Основни адреси:

- `/`
- `/map.html`
- `/missions.html`
- `/auth.html`
- `/profile.html`
- `/student.html`

Production build:

```bash
npm run build
```

Преглед на production build:

```bash
npm run preview
```

Няма конфигурирана автоматизирана test команда. Минималната текуща проверка е успешен Vite build, заедно с проверка на страниците, навигацията, responsive поведението, достъпността и липсата на хоризонтално препълване.
